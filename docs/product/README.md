# 产品说明（活文档）

本目录是 TripWhisper **当前已实现产品** 的单一事实来源：信息架构、模块、交互、业务规则，以及与代码目录的对应关系。

它描述的是仓库里正在运行的体验版，不是路线图承诺。讨论稿里尚未落地的能力，不得写成本目录中的「已实现」。

## 更新节奏（必守）

合并会改变用户可见行为或业务规则的 PR 时，**同一 PR 内**更新本目录。不要把文档留到「以后补」。

需要同步的典型改动：

- 新增 / 重命名 / 删除标签页或模块入口
- 生成、预订、重排、记账、恢复等规则变化
- 共享数据形状变化（`Journey`、`Expense`、localStorage schema）
- 演示数据与实时事实的边界变化
- 已知缺口被 Issue 合入后，把「未实现」改成「已实现」，并改对应章节

建议在 PR 说明里写一句：

- 改了哪些 `docs/product/` 文件，或
- 「无用户可见行为变化，文档未改」

评审时对照本目录，而不是对照讨论稿。

### 协作约定里的同一条规则

[`AGENTS.md`](../../AGENTS.md) 已把本目录列为已实现产品的活文档。影响行为的实现 PR 不要只改代码。[`.github/PULL_REQUEST_TEMPLATE.md`](../../.github/PULL_REQUEST_TEMPLATE.md) 有对应勾选。

## 写文档时怎么对照代码

1. 先读 `app/page.tsx` 确认标签页与共享状态。
2. 再读 `components/travel/` 与 `lib/` 里该模块的函数，不要凭记忆写规则。
3. 规则数字（缓冲 15 分钟、延后 0—180、当天截止 21:00 等）以 `lib/` 常量为准。
4. 未实现的能力链到对应 Issue，不要写成即将上线。

当前实现范围的摘要见 [overview.md](./overview.md)。受约束重排细节见 [replan.md](./replan.md)。
