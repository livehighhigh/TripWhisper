# 受约束重排

对应已合入的 [Issue #3](https://github.com/3013038780-design/TripWhisper/issues/3)。入口在「每日行动卡」右侧「计划跟着你走」，不是独立标签。

用户描述变化（晚出门、少走路、下雨）后，先看预览，再确认。确认才写入**一份** `journey`，全程安排、每日卡、活动估算一起变。

手工验收证据在 [`docs/qa/issue-3/`](../qa/issue-3/)，不是产品规则本身。

## 三种入口

| 入口 | 引擎 | 条件 |
| --- | --- | --- |
| 晚出门 +「生成晚出门重排预览」 | `previewReplan` | 延后 0—180 整数分钟；可同时勾选减少步行。延后为 0 且未勾选减少步行会报错。 |
| 「少走路」快捷 | 同上，`delayMinutes: 0, reduceWalking: true` | 把步行负担高的灵活点换成附近休息。 |
| 「下雨了」快捷 | `adjust(journey, day, 'rain')` | 把当天 `outdoor` 灵活点换成室内休息。锁定与交通不动。 |

`lib/journey.ts` 的 `adjust(..., 'rest')` 仍存在并有单测，**当前 UI 不再调用它**。「少走路」走 `lib/replan.ts`。

## 预览 → 确认（写与不写）

1. 点生成或快捷后，侧栏出现「待确认的…」。此时 `journey` 不变。
2. 打开「全程安排」仍应是旧时间表。
3. 「确认重排 / 确认调整」才 `setPrevious(当前)` + `setJourney(next)`。
4. 预览里的 `next.version` 已是 `+1`，但只有确认后才成为当前版本。
5. 晚出门预览若发现 `preview.baseVersion !== journey.version`（期间行程被改过），丢弃预览并要求重做。
6. 「取消」只关预览，不写行程。

`previewReplan` 对入参 `structuredClone`，单测断言调用后原对象不变。

## 什么算锁定（不可移动）

`isFixedStop(stop)`：`stop.locked` **或** `stop.kind === '交通'`。

| 来源 | 典型例子 | 晚出门 |
| --- | --- | --- |
| 模拟已订 | 第 1 天大教堂 09:30–11:30（偏好开关） | 时段保留 |
| 用户预订 | `kind === '我的预订'` | 时段保留 |
| 交通 | 去科莫火车、返回米兰 | 时段保留 |
| 其他 | 拱廊午餐、公园、游船、街区等 | 可顺延 / 压缩 / 替换 / 移除 |

锁定项列入预览「锁定保留」，并写取舍：不会随晚出门移动。

未勾选「模拟已订」时，大教堂是灵活点，可以随晚出门往后移。

## 灵活点怎么动（晚出门）

对当天每个非锁定 stop，按原顺序：

1. 开始时间 `+ delayMinutes`，时长先保持不变。
2. 若早于「已放入结果的上一项结束 + **15 分钟**」，再往后推。
3. 开始已过当天截止 **21:00**（或 ≥ 24:00）：**移除**。
4. 后面若有锁定项：必须在其开始前留 15 分钟。空间不够则把本段压缩；压缩后时长仍不足 **30 分钟** 则**移除**。
5. 结束超过 21:00：同样先压缩到 21:00，不足 30 分钟则移除。
6. 若同时勾选减少步行且该点「步行负担高」：在新时段上换成「减少步行，原地休息」。
7. 记录变更类型：`shifted` / `shortened` / `replaced` / `removed`。

步行负担高：`outdoor`，或 `kind` 属于 艺术 / 街区 / 自然 / 游船 / 历史。

附近休息是建议，不是已核实店铺；地址沿用原点，费用示范 €10 / 人。

**其他天的 stops 原样复制，不重排。**

## 下雨（`adjust` rain）

- 锁定或交通：原样返回。
- `outdoor` 灵活点：换成室内休息，**保留原 time–end 与地址**（与晚出门的顺延不同）。
- 只改选中的那一天。`version + 1`。
- UI 同样先预览差异再确认。

## 预览必须让用户看见的四块

1. **锁定保留**：名称与原时段、原因（已订 / 交通）。
2. **受影响项目**：顺延 / 压缩 / 替代 / 移除，含旧时段 → 新时段（若有）。
3. **活动预算参考**：`estimate(旧)` → `estimate(新)`。演示估值，不是报价。少走路把付费参观换成 €10 休息时，数字可能下降。
4. **取舍说明**：例如「火车仍为 09:00，不会移动」「游船无法在返程前留 30 分钟，已移除」。条件无法完全满足时必须出现，不能 silently 挪锁定时段。

当天只有锁定项、灵活点无法移动时，取舍会说明时间表保持原样。

## 版本与恢复

- 确认：当前行程进入 `previous`，新行程 `version++`。
- 侧栏「恢复上一版」只在有 `previous` 时出现；恢复后清空 `previous`。
- `previous` **不进** localStorage。刷新后按钮消失。
- 只能退一层。从 v4 直接回 v2、版本列表、回退前差异，见 [Issue #9](https://github.com/3013038780-design/TripWhisper/issues/9)，**不要在本模块里实现**。

## 事实边界

规则重排 ≠ 实时路况、气象或票务。交通时长与活动费用仍是示范数字。用户仍须自行核实末班车、开放时间和天气。

## 代码路径

| 职责 | 路径 |
| --- | --- |
| 侧栏 UI、下雨预览、确认 / 取消 / 恢复 | `components/travel/replan.tsx` |
| 挂载、写入 `journey` / `previous` | `app/page.tsx`（`today` 侧栏） |
| 晚出门 / 少走路算法 | `lib/replan.ts`（`previewReplan`、`isFixedStop`） |
| 下雨替换 | `lib/journey.ts`（`adjust`） |
| 活动估算 | `lib/journey.ts`（`estimate`） |
| 回归 | `tests/replan.test.mjs`、`tests/journey.test.mjs` |

默认示范行程上可手工核对的例子（与 QA 一致）：

- Day 1 晚出门 60：大教堂 09:30–11:30 不动，拱廊 12:00 → 13:00。
- Day 3 晚出门 180：火车 09:00 与返程 17:00 不动；湖边可能压缩，游船可能移除。
- Day 2 少走路：城堡 / 公园等户外或步行项改为附近休息。
