# 行程体检与修复

对应已合入的 [Issue #4](https://github.com/3013038780-design/TripWhisper/issues/4)。入口是独立标签「行程体检」，「我的预订」侧栏仍保留只读摘要。

先检查，再勾选修复，再预览，最后确认。确认才写入**一份** `journey`。解析失败、预览失败或取消，原行程保持不变。

## 两种输入

| 入口 | 引擎 | 说明 |
| --- | --- | --- |
| 检查当前行程 | `inspectJourney(journey)` | 不经过文字解析。 |
| 粘贴 / 编辑文字后检查 | `parsePlanText` → `inspectJourney` | 解析结果只活在本页草稿里，确认前不写总行程。 |

文字格式：

```text
住宿：Milano Centrale

第1天 · 标题可省略
09:30-11:30 米兰大教堂 〔已订〕
12:00-13:30 拱廊散步与午餐
```

- `住宿：` 可为空，用于测「住宿缺失」。
- 活动行：`HH:MM-HH:MM 名称`，可选 `〔已订〕` / `〔交通〕`。
- `第N天` 或 `Day N`。未写到的天保持原安排。
- 名称能对上当前行程时，沿用原 stop 的地址、故事与 id；对不上则生成一条「文字导入」活动。
- 天数超出当前行程、时间非法或没有可识别行：抛错，原对象不变。

「载入示例问题」只填充文本框，用重叠、缓冲不足、锁定冲突和空住宿演示四类检测。

## 预览 → 确认（写与不写）

1. 检查后出现问题列表。此时 `journey` 不变。
2. 打开「全程安排」仍应是旧时间表。本页用 `keepMounted` 挂着，回来时预览还在。
3. 「预览选中修复」生成 `preview.next`，仍不写当前行程。
4. 「确认应用」才 `setPrevious(当前)` + `setJourney(next)`。
5. 若 `preview.baseVersion !== journey.version`，丢弃预览并要求重做。
6. 「取消」只关预览。文字检查的草稿也不写回。

`parsePlanText` / `inspectJourney` / `previewHealthFixes` 都对入参 `structuredClone` 或只读遍历，单测断言调用后原对象不变。

## 检测什么

缓冲与预订录入相同：**15 分钟**。锁定判定与重排相同：`isFixedStop` = `locked` 或 `kind === '交通'`。

| 类型 | 何时出现 | 默认可自动修？ |
| --- | --- | --- |
| 时间重叠 | 同一天两段时间交叉 | 是（只动灵活项） |
| 缓冲不足 | 按开始时间排序后相邻两项间隔 &lt; 15 分钟 | 是（只动灵活项） |
| 锁定冲突 | 上述两种且至少一项是已订或交通 | 仅当另有灵活项 |
| 住宿缺失 | `profile.hotel` 为空 | 是（写入你填写的文本） |
| 返程缺失 | 科莫日没有 `id === 'return'` | 是（插入示范 17:00–19:00） |
| 待核验 | 固定提示天气 / 开放 / 余票 | 否 |

同一对活动：有交叉只报重叠（或锁定冲突），不再重复报缓冲。两项都是已订或交通时，建议回到「我的预订」或改文字，系统不会挪时段。

## 灵活项怎么修

对选中的一对活动：

1. 已订 / 交通作锚点，只移动另一项。
2. 两项都灵活：把较晚的一项移到较早结束 + 15 分钟，时长先保持。
3. 后面若有锁定项：必须在其开始前留 15 分钟；不够则压缩，压缩后不足 30 分钟则移除灵活项。
4. 开始已过 21:00：移除。结束超过 21:00：先压缩到 21:00，不足 30 分钟则移除。
5. 住宿修复只改 `profile.hotel`，不算路。空文本会跳过并说明。

取舍与重排一样写在预览里，不能 silently 移动锁定时段。

## 事实边界

规则体检 ≠ 实时路况、气象或票务。文字导入的新活动没有核验过的地址或票价。用户仍须自行核实开放时间和交通。
